Cara Menggunakan & Mengedit di Sparx Enterprise Architect
Seluruh rancangan telah dikonfigurasi agar Anda dapat langsung membukanya, menempelkan (*paste*), atau mengeditnya secara visual di aplikasi Enterprise Architect (EA). Berikut adalah 3 cara termudah:

Metode 1: Import File XMI (Otomatis Membuka Semua Paket, Aktor, Kelas & Diagram)

  1. Buka aplikasi Enterprise Architect dan buat Project baru (misal: Penilaian_ISS.qea atau .eapx).
  2. Pada panel Project Browser, klik kanan pada Model atau Package Root.
  3. Pilih menu Import/Export → Import Package from XMI File... (atau tekan shortcut Ctrl + Alt + I).
  4. Klik tombol Browse dan pilih file:
    enterprise_architect_model.xmi yang ada di folder projek ini.
  5. Klik Import. Seluruh use case, aktor, 14 kelas (dengan atribut & method), sequence lifelines, dan entitas ERD akan langsung muncul di Project Browser EA dan siap di-drag & drop ke diagram!

Metode 2: Import Skema Basis Data DDL SQL (Otomatis Menghasilkan ERD Lengkap di EA)

  1. Di Enterprise Architect, klik ribbon tab Develop → pilih Data Modeling → klik Import DB Schema from SQL DDL.
  2. Pilih target Database Type: MySQL.
  3. Pilih file: schema_erd_enterprise_architect.sql.
  4. Centang Prompt on duplicate table dan klik Import.
  5. EA akan membuat seluruh tabel, tipe data kolom, Primary Key, dan Foreign Key secara otomatis!

Metode 3: Menggunakan Kode PlantUML (Copy-Paste Langsung)

  1. Gunakan kode PlantUML di setiap menu di samping untuk di-copy ke EA (jika menggunakan PlantUML Extension di EA) atau alat diagram lain.
  2. Semua file .puml juga telah tersimpan secara rapi di folder scratch/dfd-pt-iss/plantuml/.
Struktur 3 Aktor Sistem
Aktor Peran Utama Hak Akses & Batasan
Admin Pengelola Data & Pengaturan Sistem Kelola pengguna, data karyawan, data master (area, etika, alat, SOP), skala bobot nilai, periode penilaian, serta melihat & mencetak rekapitulasi nilai.
Supervisor (SPV) Penilai Kinerja Karyawan Lapangan Menginput skor evaluasi (Etika, Alat, SOP), mengisi catatan & rekomendasi atasan, melakukan finalisasi nilai (mengunci penilaian), serta melihat & mencetak rekapitulasi nilai.
Karyawan Pihak yang Dinilai (Cleaner Manpower) Hanya melihat hasil evaluasi miliknya sendiri yang sudah berstatus Final, dan dapat menuliskan tanggapan / feedback atas hasil tersebut.

Gambar 3.9 Entity Relationship Diagram (ERD) - Notasi Crow's Foot
Struktur database relasional 14 tabel yang ternormalisasi (3NF). Lengkap dengan tipe data MySQL, Primary Key (PK), dan Foreign Key (FK). 
erDiagram
    pengguna ||--o| karyawan : "memiliki akun"
    area ||--o{ karyawan : "menempatkan"
    karyawan ||--o{ penilaian : "dinilai"
    pengguna ||--o{ penilaian : "menilai (penilai)"
    periode ||--o{ penilaian : "periode"
    kategori_nilai ||--o{ penilaian : "klasifikasi"

    penilaian ||--|{ detail_etika : "memiliki rincian"
    penilaian ||--|{ detail_alat : "memiliki rincian"
    penilaian ||--|{ detail_sop : "memiliki rincian"
    penilaian ||--o| tanggapan_karyawan : "memiliki tanggapan"

    aspek_etika ||--o{ detail_etika : "aspek"
    skala_nilai ||--o{ detail_etika : "skor skala"
    alat_kerja ||--o{ detail_alat : "alat"
    skala_nilai ||--o{ detail_alat : "skor skala"
    sop ||--o{ detail_sop : "sop"
    skala_nilai ||--o{ detail_sop : "skor skala"
